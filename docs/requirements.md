# VidForge 需求文档

版本 0.1 · 2026-09-11

## 1. 背景与目标

用户在两类场合需要转码，而现有工具都不能很好地同时满足：

**场景 A — 个人素材归档。** 用手机、相机、运动相机、无人机拍了大量视频。原始文件过大（手机 4K HDR 一分钟可达 400MB）、编码格式不便播放、或码率远高于保存所需。希望压缩后长期存储，同时不想丢失拍摄时记录的 HDR 信息。

**场景 B — NAS 片库治理。** 同一个库里两种诉求并存：一部分影片要按收藏级画质长期保存，包含杜比视界、HDR10+、杜比全景声、无损音轨等高价值信息；另一部分只要达到流媒体画质即可，目标是体积小、播放器能直接解码播放（Direct Play）而不触发服务端转码。

现有工具的缺口：

| 工具类型 | 缺口 |
|---|---|
| HandBrake | 对杜比视界和 Atmos 的支持有限，且不说明取舍代价；参数专业但不解释后果 |
| 商业转码软件 | 画质策略是黑盒，用户无法判断结果是否达到预期 |
| ffmpeg 命令行 | 能力最全但门槛高；参数写错会**静默丢失元数据**，用户往往在看片时才发现 HDR 变灰、Atmos 没了 |

**本产品要解决的核心问题**：让非专业用户也能做出正确的转码决策，并且能验证结果确实符合预期。

## 2. 目标用户

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 素材归档者 | 拍摄量大，不懂编码参数 | 选一个场景就能得到合理结果，不要问我 CRF 是什么 |
| 片库管理者 | 懂一些概念，在意画质与元数据 | 告诉我会丢什么、为什么，让我自己权衡 |
| 专业用户 | 熟悉 ffmpeg | 让我看到最终命令，能手动覆盖任何参数 |

三类用户共用一套界面，通过参数分层（见设计文档）同时满足。

#### 3.3.1 可变帧率转固定帧率（专项）

手机拍摄的视频几乎都是可变帧率（VFR）。这类文件直接拖进 Premiere、达芬奇、Final Cut 等剪辑软件时，因为帧时间戳不规则，剪辑过程中音画会**逐渐累积失步**——越往后偏差越大。这是手机素材进入剪辑流程时最常见的问题。

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-3.12 | 将 VFR 源转换为严格固定帧率（CFR）输出，保证音视频时长精确对齐 | P0 |
| F-3.13 | 自动推荐目标帧率：优先采用源的名义帧率，并吸附到标准帧率档（23.976/24/25/29.97/30/50/59.94/60） | P0 |
| F-3.14 | 转换前明确告知将复制或丢弃多少帧，以及预期体积变化 | P0 |
| F-3.15 | 源帧率波动极端时（如录屏从 1fps 到 60fps）提示转 CFR 会大量复制帧导致体积显著增加，并给出建议 | P1 |
| F-3.16 | 同时保证音频流时间戳连续，必要时做重采样补偿 | P0 |
| F-3.17 | 「剪辑预处理」场景预设：默认转 CFR、全 I 帧或短 GOP、高码率、剪辑软件友好的编码与容器 | P1 |

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 平台 | Windows 10/11 x64、macOS 12+（Apple Silicon 与 Intel） |
| 安装包 | 单文件安装包，不要求用户预装运行时（ffmpeg 除外，但提供引导） |
| 启动速度 | 冷启动到可交互 < 2 秒；能力探测在后台进行，不阻塞界面 |
| 内存 | 空闲时 < 200MB |
| 稳定性 | 转码过程中应用崩溃不得损坏源文件；未完成的输出文件不得留在目标目录 |
| 数据安全 | **绝不自动删除或修改源文件**；任何破坏性操作需显式二次确认 |
| 长任务 | 支持连续运行数小时的批量任务，不泄漏内存、不累积句柄 |
| 可诊断性 | 每个任务保存完整命令与日志尾部，用户能一键复制用于求助 |
| 无头预留 | 核心逻辑与界面解耦，便于后续提供命令行版本 |

## 5. 明确不做

| 项 | 原因 |
|---|---|
| 蓝光 AACS / BD+ 解密 | 法律风险。建议用户先用 MakeMKV 解密成 MKV |
| 杜比全景声 / DTS:X 的重新编码 | 需要 Dolby / DTS 商业授权，任何公开 ffmpeg 构建都做不到 |
| 视频剪辑、调色、特效 | 定位是转码工具，不是编辑器 |
| 在线流媒体下载 | 超出范围 |
| 字幕 OCR（PGS 转 SRT） | 依赖重、准确率不稳定，v1 之后再评估 |

## 6. 验收标准

v1 视为达标需满足：

1. 在一台未预装 ffmpeg 的 Windows 机器上，应用能正确提示并引导用户解决。
2. 手机拍摄的 HDR 视频经"素材归档"预设转码后，用 ffprobe 可验证 HDR10 元数据完整保留，体积显著下降，画面无肉眼可见劣化。
3. 同一文件经"流媒体直出"预设转码后输出为 8bit SDR，色调映射结果正常（不发灰、高光不过曝），MP4 带正确的 codec tag 与 faststart。
4. 带杜比视界的素材经归档预设（勾选保留杜比视界）转码后，ffprobe 可验证输出含杜比视界配置记录与逐帧 RPU。
5. 多音轨 + PGS 字幕的 MKV 经"高画质收藏"转码后，全部音轨、字幕、章节保留，无损音轨未被重新编码。
6. 上一条的文件若强制输出为 MP4，界面必须在转码前明确提示将丢失哪些内容，并提供切换容器的修正操作。
7. 在没有可用硬件编码器的环境下，全部预设仍能正常完成，且界面说明了为何使用软编。
8. 批量导入 20 个混合格式文件，队列全部完成，每个任务都有保真度报告；中途强制结束应用后重启，队列可恢复。
9. 手机拍摄的可变帧率视频经"剪辑预处理"预设转码后，ffprobe 可验证输出为严格固定帧率（`r_frame_rate` 与 `avg_frame_rate` 一致、帧间隔恒定），且视频与音频时长差小于 1 帧时长。
10. 所有 P0 功能点均有对应自动化测试或手动验证记录。
